# 四层架构与生成链路

> 状态：现行 ｜ 版本：v1.2.0 ｜ 2026-11-09 建档

**TL;DR**：一次生成的完整旅程＝YAML 配置 → CLI 解析 → ConfigLoader 加载校验 → FieldBuilder 类型转换 → gen_*.py 组装上下文 → TemplateRenderer 渲染全部 .j2 → 落盘六段产物。模板零类型判断零字符串转换——全部预处理在 Python 侧完成。

## 一、四层职责表

| 层 | 件（行数） | 职责 |
|---|---|---|
| 入口 | `generator.py`（~900 行） | CLI 解析、ConfigIndexer 索引、Generator 分发、ReportWriter 报告（stdout 捕获回放） |
| 公共 | `config_loader.py`（689） | YAML 读取＋校验分离；推导计算字段（PascalCase / 表名 / API 路径 / package_path） |
| 公共 | `field_builder.py`（569） | 字段类型转换：YAML type → FieldDefinition（Java / SQL / Vue / MyBatis 四端类型＋24 个扁平属性） |
| 公共 | `template_renderer.py`（507） | Jinja2 渲染引擎；StrictUndefined 模式＋DRY_RUN 旗标＋snake/camel/pascal 过滤器 |
| 模式 | `gen_single.py`（90）～ `gen_master_details_tabs_dialog_file.py`（428）× 14 件 | 每模式一个 `generate()` 函数，由 generator.py 统一分发 |
| 模板 | `templates/{mode}/` × 12 目录 | 每模式一组 Jinja2 模板（44~65 个 .j2），六段编号组织 |
| 配置 | `config/test/` 24 个 YAML | 声明业务字段＋模式＋域，生成器的唯一输入 |

## 二、生成链路（数据流）

```
YAML 配置文件
    │
    ▼
CLI 解析（generator.py main()）
    ├── --list-modes / --version / -h ──→ 直接输出退出
    ├── -u / --update-index ──→ ConfigIndexer.scan_configs() → index.json
    └── config.yml [output_dir] [--module] [--mode] [--dry-run] [--validate]
            │
            ▼
    Generator.__init__(config_path, output_dir, dry_run)
            │
            ├── ConfigLoader.load()          ← 读取 YAML，补 project.group 默认值
            ├── ConfigLoader.validate()      ← 校验必填字段＋模式合法性
            │
            ▼
    Generator.generate(module_code, mode_override)
            │
            ├── 遍历 modules，按 mode 分发：
            │     SINGLE_MODES     → gen_single / gen_single_with_file
            │     MASTER_DETAIL_*  → gen_master_detail / gen_master_details_tabs / ...
            │     MULTI_TABLE_*    → gen_multi_table / gen_multi_table_with_file
            │
            ▼
    gen_*.py generate(config_loader, field_builder, renderer_class, template_dir, output_dir, project_info, module)
            │
            ├── config_loader.enrich_module(module)   ← 补计算字段
            ├── field_builder.build_fields(fields)    ← 逐字段转 FieldDefinition
            ├── field_builder.ensure_status_fields()  ← status_toggles 自动补列
            │
            ├── context = {
            │     'module': module,           ← 含 code/domain/mode/api_path 等
            │     'fields': fields,           ← List[FieldDefinition]
            │     'non_toggle_fields': ...,   ← 排除 toggle 字段的子集
            │     'project': project_info,    ← 含 name/code/version/group
            │     'generated_date': 'YYYY-MM-DD',
            │     'has_date_field': bool,     ← 按需导 LocalDate import
            │     'has_datetime_field': bool,
            │ }
            │
            ▼
    renderer.render_all(context, module_output_dir)
            │
            ├── 扫描 templates/{mode}/ 全部 .j2 + 静态文件
            ├── [DRY_RUN=True] → 仅打印路径，零落盘
            ├── [DRY_RUN=False] → 渲染并写入 out/{domain}/{code}/
            │
            ▼
    产物：out/{domain}/{code}/ 六段 + .manifest.json
    报告：output/gen_*.txt + log_*.txt（ReportWriter）
```

## 三、关键机制

### DRY_RUN（预览零落盘）

`template_renderer.py` 模块级旗标 `DRY_RUN = False`，由 Generator 按需设为 True。守五处写点：

| 写点 | 位置 | 守卫 |
|---|---|---|
| 模板渲染 | `render_to_file()` | DRY_RUN 时打印路径 |
| 静态复制 ×2 | `render_all` / `render_all_with_prefix` | 同上 |
| 前置 mkdir ×2 | 同上两方法头部 | DRY_RUN 时跳过 |
| 清单写入 | `Generator._write_manifest()` | DRY_RUN 时跳过 |
| 报告目录 | `ReportWriter.__init__` mkdir | DRY_RUN 时跳过 |

另有 `gen_multi_table*.py` 中的独立 `views_output_dir.mkdir` 也由 DRY_RUN 守卫。

### StrictUndefined

Jinja2 Environment 的 `undefined=StrictUndefined`——模板引用未定义变量直接抛 `UndefinedError`，而非渲染为空字符串。这保证了模板中的拼写错误（如 `{{ filed.name }}`）会在生成时立刻暴露，而不是静默生成错误代码。

### stdout 捕获回放

`ReportWriter.capture_start()` 将 `sys.stdout` 替换为 Tee 管道（同时写终端和内存缓冲），`capture_end()` 恢复。生成过程中的所有 print 输出被捕获，最终写入 `output/log_*.txt` 日志文件。

## 四、新增一种生成模式的步骤

```
1. cp -r templates/single templates/你的模式/
   → 修改模板内容（.j2 文件）
2. cp module/gen_single.py module/gen_你的模式.py
   → 修改上下文组装逻辑
3. 在 generator.py 注册：
   VALID_MODES 追加模式名
   对应 MODES 列表追加
   import 并加入分发字典
4. 在 config_loader.py 的 VALID_MODES 追加
5. 在 config/test/ 新增测试配置 YAML
```
