# 变量与过滤器

> 状态：现行 ｜ 2026-11-09 建档

**TL;DR**：模板可用变量来自 Python 侧组装的 context 字典；自定义过滤器注册在 `template_renderer.py` 的 `_register_filters()`。核心原则：模板是纯展示层，变量已预处理，模板只做引用。

## 一、上下文变量全表

### 模块级（context['module']）

| 变量 | 类型 | 说明 |
|---|---|---|
| module.code | str | 模块编码（snake_case，如 `t1000`） |
| module.name | str | 模块中文名 |
| module.domain | str | 业务域编码 |
| module.mode | str | 生成模式 |
| module.description | str | 模块描述 |
| module.api_path | str | API 路径前缀（如 `/test/t1000`） |
| module.package_path | str | 包路径（如 `test.t1000`，主从系用） |
| module.code_pascal | str | PascalCase（如 `T1000`） |
| module.domain_pascal | str | 域名 PascalCase |
| module.has_batch_operations | bool | 是否有批量操作 |
| module.sub_tables | list | 子表配置列表（主从系独有） |

### 字段级（context['fields'] 中每个 FieldDefinition）

| 变量 | 类型 | 说明 |
|---|---|---|
| field.name | str | 字段名（snake_case） |
| field.label | str | 中文标签 |
| field.type | str | YAML 类型 |
| field.required | bool | 是否必填 |
| field.java_type | str | Java 类型 |
| field.sql_type | str | SQL 类型 |
| field.sql_length | str | SQL 长度 |
| field.vue_component | str | Vue 组件 |
| field.mybatis_jdbc_type | str | MyBatis 类型 |
| field.column_name | str | 列名（= name） |
| field.name_camel | str | camelCase |
| field.name_pascal | str | PascalCase |
| field.options_json | str | select 选项 JSON |
| field.default_value | Any | 默认值 |
| field.maxlength | int | 最大长度 |
| field.placeholder | str | 输入提示 |

### 项目级（context['project']）

| 变量 | 类型 | 说明 |
|---|---|---|
| project.name | str | 项目名 |
| project.code | str | 项目编码 |
| project.version | str | 项目版本 |
| project.group | str | 包前缀（默认 `com.libra``） |

### 控制变量

| 变量 | 类型 | 说明 |
|---|---|---|
| generated_date | str | 生成日期 `YYYY-MM-DD` |
| has_date_field | bool | 有 date 类型字段（控制 LocalDate import） |
| has_datetime_field | bool | 有 datetime 类型字段 |
| non_toggle_fields | list | 排除 status_toggles 的字段子集 |
| include_runtime | bool | 是否渲染 _runtime/ 目录 |

## 二、自定义过滤器

注册在 `template_renderer.py` 的 `_register_filters()`：

| 过滤器 | 输入→输出 | 示例 |
|---|---|---|
| `camel` | PascalCase→camelCase | `HonorName` → `honorName` |
| `snake_to_camel` | snake_case→camelCase | `honor_name` → `honorName` |
| `snake_to_pascal` | snake_case→PascalCase | `honor_name` → `HonorName` |
| `date` | timestamp→date str | `1700000000` → `2023-11-15` |
| `year` | timestamp→year | `1700000000` → `2023` |

### 使用示例

```jinja
{{ field.name | snake_to_pascal }}    {# create_time → CreateTime #}
{{ field.name | snake_to_camel }}     {# create_time → createTime #}
{{ module.code | camel }}             {# T1000 → t1000 #}
```

## 三、模板条件渲染

```jinja
{# 按需导入 #}
{% if has_date_field %}import java.time.LocalDate;{% endif %}
{% if has_datetime_field %}import java.time.LocalDateTime;{% endif %}

{# 批量操作 #}
{% if module.has_batch_operations %}
import {{ project.group }}.layer.bis.{{ module.domain }}.{{ module.code }}.entity.param.{{ module.domain_pascal }}{{ module.code_pascal }}BatchUpdateParam;
{% endif %}

{# 遍历字段 #}
{% for field in fields %}
private {{ field.java_type }} {{ field.name_camel }};
{% endfor %}

{# 主从系子表遍历 #}
{% for sub in module.sub_tables %}
<el-tab-pane label="{{ sub.name }}" name="{{ sub.code }}">
</el-tab-pane>
{% endfor %}
```

## 四、StrictUndefined 行为

引用未定义变量直接抛 `UndefinedError`（不渲染为空字符串）：

```jinja
{{ field.not_exist }}    {# ← 直接报错，不会输出空 #}
{{ filed.name }}          {# ← 拼写错误也报错（filed≠field）#}
```

这保证了模板中的拼写错误在生成时立刻暴露。
