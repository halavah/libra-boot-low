# 02. Design规范

> 适用范围：`01-design/` 目录下 4 个设计文档
> 定位：首次后端初始化时产出的设计快照

---

## 一、目录定位

`01-design/` 是后端开发**首次初始化阶段**的产出物，记录了编码前的完整设计决策。

| 文件 | 内容 | 状态 |
|------|------|------|
| `api.md` | 全模块 API 设计（78 接口，按 Controller/区域分组） | **冻结**（不再更新） |
| `database.md` | 全模块数据库设计（21 张表，字段/索引/枚举） | **冻结**（仅结构变更触发同步） |
| `model.md` | 全模块数据模型（17 张表字段索引/三层结构/业务流关联） | **冻结**（仅结构变更触发同步） |
| `ui.md` | 全模块 UI 设计（页面/组件/交互） | **冻结**（不再更新） |

---

## 二、冻结规则

### 2.1 全部冻结

- 四个文件均在**首次初始化**时生成，作为设计基线
- 后续不再更新（实际接口/数据库/页面以代码和 DDL 为准）
- 如需查阅当前状态，直接读 Controller 源码、`server_exec.sql` 或源码

### 2.2 结构变更触发同步（仅 database.md + model.md）

| 变更类型 | 是否触发 database.md/model.md 同步 |
|---------|--------------------|
| 新增表 / 删除表 / 新增字段 / 删除字段 / 字段类型变更 / 表关系变更 | ✅ 触发同步 |
| 纯 Mock 数据修复 / 状态码值补充 / 字段 COMMENT 调整 | ❌ 不触发同步 |

结构变更后，按实际 DDL 同步 `database.md`（DDL 字段定义快照）和 `model.md`（17 表字段索引/三层结构图/业务流关联）。`api.md` 和 `ui.md` 严格冻结，任何变更都不触发同步。

---

## 三、文件内容概要

### api.md

按 7 个 Controller 分组，每个接口记录：

| 字段 | 说明 |
|------|------|
| 编号 | A1、B2 等区域编号 |
| 方法 | GET / POST |
| 路径 | `/{project}/{role}/xxx` |
| 说明 | 一句话功能描述 |
| 入参 | 参数名 + 类型 + 是否必填 |
| 出参 | 返回结构 |

### database.md

按 21 张表分组，每张表记录：

| 字段 | 说明 |
|------|------|
| 表名 | `{prefix}_xxx` |
| 说明 | 业务含义 |
| 字段列表 | 列名 + 类型 + 默认值 + 说明 |
| 索引 | 主键/唯一/普通索引 |
| 枚举值 | 状态字段的可选值 |

### model.md

按 17 张业务表分组，每张表记录：

| 字段 | 说明 |
|------|------|
| 表名 | 业务表英文名（如 `demo_product`） |
| 字段索引 | 每个字段的中文名+类型+默认值+说明 |
| 三层结构 | 该表在数据层/业务层/视图层的位置 |
| 业务流关联 | 该表参与的 5 大业务流（用户选购/订单审批报送/积分发放消费/供应商套餐审核/HR 同步） |
| 颜色分组 | 按业务职责的 6 色分组（A/B/C/D 模板） |

### ui.md

按角色分组，记录页面结构和交互设计。
