# 01. Agent规范

## 目录结构

```
layer/server/
├── AGENT.md
├── 00-inbox/
├── 01-design/           ← api.md(冻结) database.md(冻结) model.md(冻结) ui.md(冻结)
├── 02-sql/              ← server_enum.md server_exec.sql server_mock_XX_*.sql
├── 02-sql-scripts/      ← run_mock.sh run_mock.py
├── 03-http/             ← 01-sys-auth~07-wsdl.http 10-base~16-points.http index.md
├── 03-http-scripts/     ← test_mock.sh gen_mock.py
├── 05-exec/             ← exec_sqls.py（编辑 EXEC_FILES 选择文件，exec/→bak/ 清理）
└── 06-out/
```

---

## 关键规则

- `api.md` / `database.md` / `model.md` / `ui.md` 均冻结，仅用于初次初始化
- 结构变更（新增表/字段/关系）后必须同步 `database.md` + `model.md`；纯数据值变更不触发同步
- Mock 文件命名：`server_mock_XX_表名.sql`，一文件一表，编号即执行顺序
- Mock 幂等：业务表 `TRUNCATE + INSERT`；`sys_user` 用 `INSERT ... ON DUPLICATE KEY UPDATE`
- HTTP 文件编号：系统管理 `01-07`，业务接口 `10-16`，1 Controller = 1 文件
- HTTP 请求编号与 `@ApiOperation("A1-xxx")` 对齐
- 禁止 `DROP TABLE` / `CREATE TABLE` 出现在 Mock 文件中
- run_mock 脚本：改动了 02-sql/ 下的 SQL 文件后必须执行 02-sql-scripts/ 下的 run_mock 验证；模式 0=表结构+数据，1=仅表结构，2=仅数据；--yes 跳过确认
- HTTP 接口测试：默认不执行，仅在用户明确要求时才触发；用户要求时执行前必须询问确认；测试完成后模拟用户数据可能被修改，需 run_mock.sh 0 --yes 重灌
- server_mock_00_sys_user.sql 是固定模拟用户文件（文件名为已知常量），03-http 相关操作禁止修改此文件的数据

## 命令速查

```bash
# 执行完整 DDL
cd .claude/unit/layer/server/02-sql
mysql -h <db-host> -u root -p<db-password> demo_db < server_exec.sql

# Mock 数据执行
cd .claude/unit/layer/server/02-sql-scripts && ./run_mock.sh 0 --yes   # → 全量重置+灌数据

# HTTP 接口测试
cd .claude/unit/layer/server/03-http-scripts && ./test_mock.sh   # → 接口测试

# 通用 SQL 执行（编辑 EXEC_FILES 选择文件，临时 SQL 放 exec/，执行后移 bak/）
cd .claude/unit/layer/server/05-exec && python3 exec_sqls.py

# 后端启动
cd demo-server && mvn clean package -DskipTests && java -jar target/demo-server-1.0.0.jar
```
