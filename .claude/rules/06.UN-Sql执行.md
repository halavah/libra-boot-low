# 06. Sql执行

> 适用范围：`.claude/unit/layer/server/02-sql/`、`02-sql-scripts/`、`05-exec/`
> 目标：明确 SQL 执行入口，避免把 DDL、Mock 数据、临时 SQL 混用。

---

## 一、总览

| 方式 | 入口 | 适用场景 | 是否推荐日常使用 |
|------|------|----------|------------------|
| mysql 原生命令 | `mysql ... < xxx.sql` | 快速执行单个 SQL 文件，尤其是完整 DDL | 临时验证可用 |
| 通用 SQL 工具 | `05-exec/exec_sqls.py` | 临时 SQL、备份恢复、大 INSERT、分批提交 | 推荐用于临时执行 |
| Mock 初始化脚本 | `02-sql-scripts/run_mock.*` | 标准建表、重灌 Mock 数据、HTTP 测试前后恢复环境 | 推荐作为标准入口 |

---

## 二、方式一：mysql 原生命令

### 2.1 完整 DDL

```bash
# 1. 执行完整 DDL
cd .claude/unit/layer/server/02-sql
mysql -h <db-host> -u root -p<db-password> demo_db < server_exec.sql
```

### 2.2 单个 Mock 文件

```bash
# 1. 执行单个 Mock SQL
cd .claude/unit/layer/server/02-sql
mysql -h <db-host> -u root -p<db-password> demo_db < server_mock_16_festival_config.sql
```

### 2.3 适用边界

| 场景 | 建议 |
|------|------|
| 快速验证某个 SQL 文件语法 | 可用 mysql 原生命令 |
| 执行完整 `server_exec.sql` | 可用 mysql 原生命令 |
| 按编号顺序灌全部 Mock | 改用 `run_mock.sh 2 --yes` |
| 需要自动重连、分批 commit | 改用 `exec_sqls.py` |

**注意**：原生命令没有项目级保护，执行前必须确认目标库和 SQL 文件。

## 三、方式二：05-exec/exec_sqls.py

### 3.1 目录职责

| 目录 | 职责 | 说明 |
|------|------|------|
| `05-exec/exec/` | 临时 SQL | 当前要执行的 SQL 放这里 |
| `05-exec/bak/` | 已执行 SQL 归档 | 执行后从 `exec/` 移入 |
| `05-exec/struc/` | 系统 DDL 结构 | 只读，不要随意修改 |
| `05-exec/exec_sqls.py` | 执行入口 | 编辑 `EXEC_FILES` 控制执行清单 |

### 3.2 标准流程

```bash
# 1. 放入临时 SQL
cp /path/to/temp.sql .claude/unit/layer/server/05-exec/exec/

# 2. 编辑 EXEC_FILES
cd .claude/unit/layer/server/05-exec
```

```python
# 3. 在 exec_sqls.py 顶部维护执行清单
EXEC_FILES = [
    'exec/temp.sql',
]
```

```bash
# 4. 执行
python3 exec_sqls.py

# 5. 执行完成后归档
mv exec/temp.sql bak/
```

### 3.3 支持能力

| 能力 | 说明 |
|------|------|
| DDL 模式 | 文件不含 INSERT 时，按 DDL 整体执行 |
| INSERT 模式 | 文件含 INSERT 时，逐行执行并分批 commit |
| 自动重连 | 长 INSERT 任务中通过超时和 ping 保活 |
| 自定义连接 | 可通过 `--host`、`--port`、`--user`、`--password`、`--database` 覆盖 |

```bash
# 1. 自定义数据库连接和批量提交阈值
cd .claude/unit/layer/server/05-exec
python3 exec_sqls.py --host <db-host> --port 3306 --batch 500
```

### 3.4 禁止事项

- **禁止**把 `05-exec/exec_sqls.py` 当成 HTTP 测试后的重灌入口。
- **禁止**长期保留 `exec/` 下已执行文件。
- **禁止**修改 `struc/` 下系统 DDL，除非任务明确要求。

## 四、方式三：02-sql-scripts/run_mock

### 4.1 Linux/Mac

```bash
# 1. 交互式执行
cd .claude/unit/layer/server/02-sql-scripts
./run_mock.sh

# 2. 非交互：表结构 + Mock 数据
./run_mock.sh 0 --yes

# 3. 非交互：仅表结构
./run_mock.sh 1 --yes

# 4. 非交互：仅 Mock 数据
./run_mock.sh 2 --yes
```

### 4.2 Windows

```powershell
# 1. 交互式执行
cd .claude/unit/layer/server/02-sql-scripts
.\run_mock.ps1

# 2. 非交互：表结构 + Mock 数据
.\run_mock.ps1 0 --yes
```

### 4.3 Python 直接入口

```bash
# 1. 直接调用核心脚本
cd .claude/unit/layer/server/02-sql-scripts
python3 run_mock.py 0 --yes
```

### 4.4 模式说明

| 模式 | 含义 | 执行文件 |
|------|------|----------|
| `0` | 表结构 + Mock 数据 | `server_exec.sql` + `server_mock_XX_*.sql` |
| `1` | 仅表结构 | `server_exec.sql` |
| `2` | 仅 Mock 数据 | `server_mock_XX_*.sql` |

**强制**：修改 `02-sql/` 下任何 SQL 后，必须执行 `02-sql-scripts/run_mock` 验证。

---

## 五、选择建议

| 需求 | 推荐方式 |
|------|----------|
| 重置完整测试库 | `run_mock.sh 0 --yes` |
| 只重灌 Mock 数据 | `run_mock.sh 2 --yes` |
| 改了 DDL 需要验证 | `run_mock.sh 1 --yes` 或 `run_mock.sh 0 --yes` |
| 临时补字段/修数据 | `05-exec/exec_sqls.py` |
| 快速跑一个 SQL 文件 | mysql 原生命令 |
| HTTP 测试后恢复数据 | `run_mock.sh 0 --yes` |

---

## 六、安全提醒

- 执行前确认目标库：`<db-host>:3306/demo_db`。
- 涉及 `server_exec.sql` 或模式 `0/1` 时会重建表结构，数据会被重置。
- HTTP 测试会改动模拟数据，测试后需要使用 `run_mock.sh 0 --yes` 恢复。
- `server_mock_00_sys_user.sql` 是固定模拟用户文件，非明确需求不要修改。
