## 1. 常量前置

### 1.1 常量区格式

所有可配置项必须在文件顶部显式声明为常量。

**Python 格式**:

```python
# 1. 常量区
DB_HOST     = "<db-host>"
DB_PORT     = 3306
DB_USER     = "root"
DB_PASSWORD = "<db-password>"
DB_NAME     = "demo_db"

CONNECT_TIMEOUT    = 600
READ_TIMEOUT       = 600
WRITE_TIMEOUT      = 600
DEFAULT_BATCH_SIZE = 1000
# 1. 常量区结束
```

**Shell 格式**:

```bash
# 1. 常量区
DEFAULT_BASE_URL="http://localhost:5980"
OUT_DIR_PREFIX="../06-out"
REPORT_DIR="html-report"
DEV_SERVER_WAIT_SECONDS=60
# 1. 常量区结束
```

**PowerShell 格式**:

```powershell
# 1. 常量区
$DefaultBaseUrl       = "http://localhost:5980"
$OutDirPrefix         = "..\06-out"
$ReportDir            = "html-report"
$DevServerWaitSeconds = 60
# 1. 常量区结束
```

**JavaScript 格式**:

```javascript
// 1. 常量区
const DEFAULT_BASE_URL   = 'http://localhost:5980';
const OUT_DIR_PREFIX     = '../06-out';
const REPORT_DIR         = 'html-report';
const TIMEOUT_MS         = 30000;
// 1. 常量区结束
```

### 1.2 必须前置的常量类别

| 类别 | 示例 | 说明 |
|------|------|------|
| **连接配置** | `DB_HOST`、`BASE_URL` | 任何外部服务地址 |
| **超时时间** | `CONNECT_TIMEOUT`、`GOTO_TIMEOUT` | 毫秒或秒，单位在命名中体现 |
| **路径/目录** | `OUT_DIR_PREFIX`、`SCRIPT_DIR` | 使用相对路径时标注基准 |
| **阈值/批量** | `BATCH_SIZE`、`MAX_RETRY` | 任何用于判断的数值边界 |
| **命令/模板** | `DEV_SERVER_CMD`、`DEFAULT_TOKEN_PREFIX` | 可执行命令或字符串模板 |
| **枚举集合** | `VALID_ROLES`、`WEB_PROJECT_DIRS` | 数组/字典形式，禁止散落 |

### 1.3 禁止项

-  `timeout: 30000` 等魔法数字
-  `BASE_URL="http://localhost:5980"` 直接写在函数里
-  `sleep 1` / `waitForTimeout(2000)` 没有对应的常量名
-  同一常量多处重复定义

每个函数必须有 Google Style Docstring。

```python
def derive_table_name(sql_file):
    """
    从 SQL 文件名自动推导目标表名。

    规则：
        1. 取文件名（不含路径）
        2. 去掉 .sql 后缀
        3. 去掉日期后缀（如 _20260515）
        4. 去掉 _ddl 后缀

    参数:
        sql_file (str): SQL 文件路径

    返回:
        str: 推导出的表名

    示例:
        >>> derive_table_name("bak/sys_org_20260515.sql")

    """
```

- 复杂逻辑必须加行内注释，说明**为什么**而非**做了什么**
- 分段代码用区域注释分隔

```python
# ==============================================================================
# 2. DDL 模式执行（纯建表语句，直接整文件执行）

```

### 2.4 禁止项

-  无文件头注释
-  函数无 Docstring
-  注释与代码不符（修改代码必须同步改注释）
-  用注释保留废弃代码（直接删除，用 Git 找回）

## 2.1 交互输入内联规范

Shell 交互式脚本中，菜单输入提示必须与输入光标在同一行显示。

**Bash**:

```bash
# ✅ 正确：read -p 内联显示
read -p "  请输入编号 (1-8) [q/9 退出]: " main_choice
```

**PowerShell**:

```powershell
# ✅ 正确：Read-Host 天然内联
$choice = Read-Host "请输入编号 (1-8) [q/9 退出]"
```

## 3. 路径处理

### 3.1 脚本目录基准

所有相对路径必须以 `SCRIPT_DIR`（脚本所在目录）为基准。

```python
# 1. 正确
SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
sql_file = os.path.join(SCRIPT_DIR, 'bak', 'sys_org.sql')

# 2. 错误
sql_file = 'bak/sys_org.sql'  # 依赖执行目录
```

### 3.2 跨平台路径

| 语言 | 正确做法 | 错误做法 |
|------|---------|---------|
| Python | `pathlib.Path` 或 `os.path.join` | 硬编码 `/` 或 `\` |
| Shell | `$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)` | `pwd` 或相对路径 |
| PowerShell | `Split-Path -Parent $MyInvocation.MyCommand.Definition` | `$PSScriptRoot` 以外的写法 |
| Node.js | `path.resolve(__dirname, '...')` | 硬编码相对路径 |

## 4. 错误处理

### 4.1 连接类操作

任何网络/数据库连接必须：

1. 带超时参数
2. 有重连/保活机制
3. 失败时给出明确错误信息

```python
# 1. 建立连接（带超时）
conn = pymysql.connect(
    host=db_config['host'],
    port=db_config['port'],
    connect_timeout=CONNECT_TIMEOUT,
    read_timeout=READ_TIMEOUT,
    write_timeout=WRITE_TIMEOUT,
)

# 2. 执行 + 回滚 + 关闭
try:
    cursor = conn.cursor()
    cursor.execute(stmt)
    conn.commit()
except Exception as e:
    conn.rollback()
    print(f"ERROR: {e}")
    raise
finally:
    conn.close()
```

### 4.2 文件操作

```python
if not os.path.exists(sql_file):
    raise FileNotFoundError(f"SQL 文件不存在: {sql_file}")
```

### 4.3 用户输入校验

```python
if not EXEC_FILES:
    print("EXEC_FILES 数组为空，请在代码开头填写要执行的 SQL 文件路径")
    sys.exit(0)
```

## 6. 环境配置

### 6.1 .env 文件加载

如果脚本需要环境变量，必须支持从 `.env` 文件加载，且不依赖外部包（如 dotenv）。

```python
def load_env(env_path='.env'):
    """加载 .env 文件，返回键值对字典。"""
    env = {}
    paths_to_try = [Path(env_path), Path(__file__).parent / '.env']
    for p in paths_to_try:
        if not p.exists():
            continue
        for line in p.read_text(encoding='utf-8').split('\n'):
            line = line.strip()
            if not line or line.startswith('#'):
                continue
            idx = line.find('=')
            if idx > 0:
                env[line[:idx].strip()] = line[idx + 1:].strip()
        if env:
            break
    return env
```

### 6.2 优先级

配置优先级从高到低：

```
环境变量 > .env 文件 > 脚本内常量默认值
```

```python
base_url = env.get('BASE_URL', DEFAULT_BASE_URL)
```

## 11. 部署脚本专项规范

> **适用范围**: `deploy-*.sh` / `deploy-*.ps1` — 远程服务器部署脚本

### 11.1 十节中文注释（部署脚本专用）

部署脚本因涉及多服务器、多仓库、配置替换、环境保护等复杂场景，**强制使用十节注释**（而非普通脚本的四节/五节）：

| 节号 | 标题 | 说明 |
|------|------|------|
| 一 | 为什么需要这个脚本 | 触发场景、解决什么痛点 |
| 二 | 两套服务器差异 | IP、用户、端口、工具链、权限差异对比 |
| 三 | 三个仓库与目录结构 | 后端/PC/H5 仓库在远端的绝对路径 |
| 四 | Git 拉取策略 | fetch + checkout -f + pull 强制更新流程 |
| 五 | 后端构建与重启 | mvn package → kill old → start new JAR → 等端口就绪 |
| 六 | 前端构建与部署 | pnpm install → build → 复制 dist → 恢复 .env |
| 七 | 配置替换策略 | sed 替换 application.yml / .env 的字段列表 |
| 八 | 环境保护机制 | .env stash/unstash、失败回滚策略 |
| 九 | 健康检查与验证 | 端口监听、curl 健康端点、HTTP 入口检查 |
| 十 | 换行符与兼容性 | .sh LF / .ps1 CRLF、bash+zsh 兼容 |

### 11.2 SSH 远程操作规范

所有远程命令通过 `ssh` 执行，封装为统一函数：

**Shell**:

```bash
run_ssh() {
    ssh -o ConnectTimeout=${SSH_TIMEOUT} -o StrictHostKeyChecking=no ${SERVER} "$1"
}
```

**PowerShell**:

```powershell
function Run-Ssh([string]$Command) {
    ssh -o ConnectTimeout=$Script:SSH_TIMEOUT -o StrictHostKeyChecking=no $Script:SERVER $Command
}
```

| 规则 | 说明 |
|------|------|
| 超时参数 | `ConnectTimeout` 使用常量（如 `SSH_TIMEOUT=10`） |
| 禁止交互确认 | `-o StrictHostKeyChecking=no` |
| 错误处理 | 检查 `$?` / `$LASTEXITCODE`，失败时打印 `[FAIL]` 并中止 |

### 11.3 sed 配置替换

通过 SSH 远程执行 `sed -i` 替换配置文件中的占位符：

```bash
# Shell 示例
run_ssh "sed -i 's|spring.datasource.url:.*|spring.datasource.url: jdbc:mysql://${DB_HOST}:${DB_PORT}/${DB_NAME}|' ${APP_YML}"
```

| 规则 | 说明 |
|------|------|
| 分隔符 | 含 `/` 的值用 `\|` 分隔，避免转义混乱 |
| 多项替换 | 逐条 sed 命令，禁止合并到单行 |
| 幂等性 | 每次部署全量替换，不依赖上次状态 |
| 1Panel vs 宝塔 | 1Panel 仅替换 DB 名称（Docker 容器内 MySQL）；宝塔需替换 11 项（Redis/MySQL/MinIO/待办URL 等） |

### 11.4 .env 环境保护机制

前端仓库的 `.env` 文件包含本地开发配置，部署时必须保护：

```
部署前：git diff --name-only HEAD -- .env
  ├─ 无改动 → 跳过
  └─ 有改动 → git stash push -m 'deploy-script-env-backup' -- .env

构建后：git stash pop 2>/dev/null
  └─ 恢复开发环境 .env
```

| 规则 | 说明 |
|------|------|
| stash 消息 | 固定 `deploy-script-env-backup`，便于识别 |
| 静默处理 | stash pop 的 `2>/dev/null` 抑制无 stash 时的错误输出 |
| 构建前保护 | **必须在** `pnpm install` 之前 stash，避免 .env 污染构建 |

### 11.5 健康检查

部署完成后执行三层验证：

| 层级 | 方法 | 说明 |
|------|------|------|
| 端口监听 | `lsof -i :${PORT}` 或 `ss -tlnp \| grep ${PORT}` | 后端 JAR 是否在监听 |
| 健康端点 | `curl -sf http://localhost:${PORT}/{project}/base/health -H 'Authorization: Bearer ${DEV_TOKEN}'` | API 可达 + Dev-Token 认证通过 |
| 前端入口 | `curl -sf http://localhost:${PORT}/` | Nginx/OpenResty 是否返回 HTML |

| 规则 | 说明 |
|------|------|
| 等待策略 | 循环检查（最多 60 秒），每 2 秒重试 |
| Dev-Token | 使用常量 `DEV_TOKEN`，与 CLAUDE.md 测试账号一致 |
| 失败输出 | 超时后打印 `[FAIL]` + 诊断建议（如查看日志） |

### 11.6 常量区扩展

部署脚本除标准 6 类常量外，还需包含：

| 类别 | 示例 | 说明 |
|------|------|------|
| SSH 连接 | `SERVER`、`SSH_TIMEOUT` | 远程服务器地址和超时 |
| 仓库路径 | `BACKEND_DIR`、`PC_REPO_DIR`、`H5_REPO_DIR` | 远程仓库绝对路径 |
