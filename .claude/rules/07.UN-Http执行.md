# 07. Http执行

> 适用范围：`.claude/unit/layer/server/03-http/`、`03-http-scripts/`
> 目标：明确 HTTP 接口的单次验证、手工测试、批量自动化测试和集合生成边界。

---

## 一、总览

| 方式 | 入口 | 是否直接发请求 | 适用场景 |
|------|------|----------------|----------|
| curl 原生命令 | `curl ...` | 是 | 快速验证单个接口 |
| `.http` 文件直接执行 | `03-http/*.http` | 是 | 在 IDE REST Client / IntelliJ HTTP Client 中逐条执行 |
| 批量测试脚本 | `03-http-scripts/test_mock.*` | 是 | 扫描并执行全部 `.http` 文件 |
| 集合生成辅助 | `03-http-scripts/gen_mock.*` | 否 | 生成 Postman/Apifox 集合后再导入执行 |

**强制**：HTTP 接口测试默认不执行，仅在用户明确要求时触发；测试完成后模拟数据可能被修改，需用 `run_mock.sh 0 --yes` 重灌。

---

## 二、方式一：curl 原生命令

### 2.1 GET 示例

```bash
# 1. 使用 Dev-Token 调用 GET 接口
curl 'http://localhost:9172/{project}/{role3}/shop/categories' \
  -H 'Authorization: demo-dev-zgh-2026' \
  -H 'Accept: application/json'
```

### 2.2 POST JSON 示例

```bash
# 1. 使用 Dev-Token 调用 POST JSON 接口
curl 'http://localhost:9172/{project}/{role1}/festivalConfig/page' \
  -H 'Authorization: demo-dev-gsda-2026' \
  -H 'Content-Type: application/json' \
  -d '{
    "current": 1,
    "size": 10
  }'
```

### 2.3 适用边界

| 场景 | 建议 |
|------|------|
| 快速确认接口是否 404/401/500 | 使用 curl |
| 验证代理后的实际路径 | 使用浏览器复制 curl |
| 批量跑多个接口 | 改用 `test_mock.sh` |
| 需要复用 `.http` 变量 | 改用 `.http` 直接执行 |

## 三、方式二：03-http/*.http 直接执行

### 3.1 文件变量

`.http` 文件头部统一声明 `@base_url` 和 `@token`：

```http
@base_url = http://localhost:9172/{project}/{role1}
@token = demo-dev-gsda-2026
```

`@token` 使用后端 Dev-Token，常用值如下：

| 角色 | Token |
|------|-------|
| 路衍管理员 | `demo-dev-admin-2026` |
| 路衍管理测试 | `demo-dev-gsda-2026` |
| 子公司管理测试 | `demo-dev-gsdb-2026` |
| 用户测试 | `demo-dev-zgh-2026` |
| 供应商测试 | `demo-dev-gys-2026` |

### 3.2 请求写法

```http
### 1. 查询活动配置
POST {{base_url}}/festivalConfig/page
Authorization: {{token}}
Content-Type: application/json

{
  "current": 1,
  "size": 10
}
```

### 3.3 适用边界

| 场景 | 建议 |
|------|------|
| 手工执行某个接口 | 使用 `.http` 文件直接执行 |
| 对照 Controller 和接口编号 | 使用 `.http` 文件 |
| 想一次执行全部接口 | 改用 `test_mock.sh` |
| 需要复制给浏览器或终端 | 转成 curl |

**注意**：`.http` 直接执行依赖编辑器支持；项目内只保存请求定义，不保存执行结果。

## 四、方式三：03-http-scripts/test_mock 批量执行

### 4.1 Linux/Mac

```bash
# 1. 交互式执行
cd .claude/unit/layer/server/03-http-scripts
./test_mock.sh

# 2. 跳过数据库初始化，仅执行 HTTP 测试
SKIP_DB_INIT=1 ./test_mock.sh
```

### 4.2 Windows

```powershell
# 1. 交互式执行
cd .claude/unit/layer/server/03-http-scripts
.\test_mock.ps1

# 2. 跳过数据库初始化，仅执行 HTTP 测试
$env:SKIP_DB_INIT="1"; .\test_mock.ps1
```

### 4.3 Python 直接入口

```bash
# 1. 直接运行核心脚本
cd .claude/unit/layer/server/03-http-scripts
python3 test_mock.py

# 2. 指定 Bearer Token 变量
BEARER_TOKEN=demo-dev-gsda-2026 python3 test_mock.py

# 3. 跳过数据库初始化
SKIP_DB_INIT=1 python3 test_mock.py
```

### 4.4 交互菜单

`test_mock.sh` 无参数运行时提供菜单：

| 选项 | 含义 |
|------|------|
| `1` | 全量执行：重置数据库 + 运行全部接口测试 |
| `2` | 仅运行测试：不重置数据库 |
| `3` | 仅重置数据库 |
| `4` | 运行指定接口：输入接口名，逗号分隔 |
| `0` | 退出 |

### 4.5 执行机制

| 环节 | 说明 |
|------|------|
| 扫描目录 | 自动扫描 `../03-http/*.http` |
| 变量替换 | 支持 `@base_url`、`@token` 和 `{{变量名}}` |
| 数据初始化 | 默认调用 `../02-sql-scripts/run_mock.py 0 --yes` |
| 跳过初始化 | 设置 `SKIP_DB_INIT=1` |
| 日志输出 | 输出到 `../06-out/mock_YYYYMMDD_HHMMSS.txt` |

**注意**：批量测试可能触发新增、修改、删除、状态流转等接口，执行后应按需重灌 Mock 数据。

## 五、辅助链路：gen_mock 生成集合

`gen_mock` 不直接发 HTTP 请求，只解析 `.http` 文件并生成 Postman/Apifox Collection。

### 5.1 Linux/Mac

```bash
# 1. 生成集合
cd .claude/unit/layer/server/03-http-scripts
./gen_mock.sh
```

### 5.2 Windows

```powershell
# 1. 生成集合
cd .claude/unit/layer/server/03-http-scripts
.\gen_mock.ps1
```

### 5.3 Python 直接入口

```bash
# 1. 默认生成
python3 gen_mock.py

# 2. 指定集合名称
python3 gen_mock.py --name "{PROJECT} Server API"

# 3. 指定 .http 目录
python3 gen_mock.py --dir ../03-http
```

| 特点 | 说明 |
|------|------|
| 输入 | `03-http/*.http` |
| 输出 | Postman Collection v2.1 JSON |
| 用途 | 导入 Postman/Apifox 后再执行 |
| 分类 | 辅助工具，不算直接 HTTP 执行方式 |

---

## 六、选择建议

| 需求 | 推荐方式 |
|------|----------|
| 快速复现一个报错接口 | curl |
| 手动调试单个接口参数 | `.http` 直接执行 |
| 一次跑完整接口回归 | `test_mock.sh` |
| 只跑接口不重置数据库 | `SKIP_DB_INIT=1 ./test_mock.sh` |
| 导入 Postman/Apifox | `gen_mock.sh` |
| 测试后恢复环境 | `../02-sql-scripts/run_mock.sh 0 --yes` |

---

## 七、安全提醒

- HTTP 测试默认不执行，必须由用户明确要求后再触发。
- 涉及状态流转、删除、发放积分、报送等接口时，测试会改变模拟数据。
- 测试完成后如需恢复标准环境，执行：

```bash
# 1. 重灌表结构和 Mock 数据
cd .claude/unit/layer/server/02-sql-scripts
./run_mock.sh 0 --yes
```
