# 03. Sql规范

> 约束对象：`02-sql/server_exec.sql`（DDL 建表脚本）、`02-sql/server_enum.md`（枚举定义文档）

---

## 一、server_exec.sql — DDL 建表脚本规范

### 1.1 文件头格式

```sql
-- ============================================================
-- {PROJECT} 全模块 DDL（建表脚本）
-- 覆盖: 按业务模块分组
-- 表数: N 张业务表（随增删实时更新）
-- 执行方式: mysql -h <db-host> -u root -p<db-password> demo_db < server_exec.sql
-- ============================================================
SET NAMES utf8mb4;
SET FOREIGN_KEY_CHECKS = 0;
```

**规则**：
- `表数` 必须与实际 `CREATE TABLE` 数量一致
- `执行方式` 中的数据库名必须正确（当前为 `demo_db`）

### 1.2 模块分隔线

```sql
-- ============================================================
-- BASE — 跨端共享基础（N 张）
-- ============================================================
```

**规则**：
- 模块名用中文，格式：`模块代号 — 模块描述（N 张）`
- `N 张` 必须与实际该模块下的表数一致
- 模块之间用 `-- ============================================================` 分隔
- **禁止**在模块分隔线内写 `"已改造"、"其中 2 张已改造"` 等历史标记

### 1.3 表区域注释

```sql
-- -----------------------------------------------------
-- 1. 订单主表
-- -----------------------------------------------------
DROP TABLE IF EXISTS `{prefix}_order_approval`;

CREATE TABLE `{prefix}_order_approval` (
  ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订单主表';
```

**规则**：
- 格式严格为：`-- -----------------------------------------------------` + `-- N. 表名` + `-- -----------------------------------------------------`
- **编号必须连续**，从 1 开始，不跳序、不重复
- **禁止**在表名后加历史标记：`（★改造）`、`（★新增 P0）`、`（★已瘦身）`、`（B 模板）`、`（C 模板）` 等
- 如果表属于某个模块，编号在该模块内连续，或全文件连续（二选一，当前采用全文件连续）

### 1.4 DROP TABLE IF EXISTS

```sql
-- -----------------------------------------------------
-- 1. 订单主表
-- -----------------------------------------------------
DROP TABLE IF EXISTS `{prefix}_order_approval`;

CREATE TABLE `{prefix}_order_approval` (
```

**规则**：
- 每张表必须有独立的 `DROP TABLE IF EXISTS`
- **禁止**在一个表的注释前放另一张表的 `DROP`（如当前第17-19行的写法）
- `DROP` 紧跟在 `-- N. 表名` 注释之后、`CREATE TABLE` 之前

### 1.5 字段定义格式

```sql
  `id`            BIGINT        NOT NULL                              COMMENT '主键ID（雪花算法）',
  `order_no`      VARCHAR(100)  DEFAULT NULL                         COMMENT '订单编号（WO-yyyyMMdd-XXXX）',
  `status`        INT           NOT NULL DEFAULT 1                   COMMENT '状态：1=已选购,2=已报送,3=待发货,4=已发货,5=已驳回',
  `is_deleted`    INT           NOT NULL DEFAULT 0                   COMMENT '逻辑删除：0=正常，1=已删除',
  `create_time`   DATETIME      DEFAULT NULL                         COMMENT '创建时间',
  `create_user`   BIGINT        DEFAULT NULL                         COMMENT '创建人ID',
  `create_dept`   BIGINT        DEFAULT NULL                         COMMENT '创建部门ID（数据权限）',
  `update_time`   DATETIME      DEFAULT NULL                         COMMENT '更新时间',
  `update_user`   BIGINT        DEFAULT NULL                         COMMENT '更新人ID',
```

**规则**：
- 反引号、字段名、类型、NULL/DEFAULT、COMMENT 四列对齐
- 类型后必须跟 `NOT NULL` 或 `DEFAULT xxx`
- COMMENT 内容简洁，**禁止**在 COMMENT 里写 `"（对齐外部系统 xxx）"`、`"（雪花算法）"` 等历史标记
- **禁止**列定义中内联 `CHARACTER SET utf8mb4` / `COLLATE utf8mb4_0900_ai_ci` 声明（MySQL 导出工具常自动添加，属于冗余）；字符集和排序规则统一由表尾 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci` 控制
- 错误：`` `name` varchar(255) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci NOT NULL``
- 正确：`` `name` varchar(255) NOT NULL``
- 时间字段统一模板：`create_time` / `create_user` / `create_dept` / `update_time` / `update_user`

### 1.6 索引定义格式

```sql
  PRIMARY KEY (`id`),
  INDEX `idx_order_no`   (`order_no`),
  INDEX `idx_user_id`    (`user_id`),
  INDEX `idx_status`     (`status`),
  INDEX `idx_dept_code`  (`dept_code`),
  INDEX `idx_holiday_id` (`holiday_id`),
  INDEX `idx_supplier_id`(`supplier_id`)
```

**规则**：
- 统一放 `PRIMARY KEY` 之后
- 命名规范：`idx_字段名`
- 多字段索引：`idx_字段1_字段2`
- UNIQUE 索引：`uk_字段名`

### 1.7 表尾格式

```sql
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订单主表';
```

**规则**：
- 必须显式写 `COLLATE=utf8mb4_0900_ai_ci`（与 sys_user 保持一致）
- COMMENT 只写表名，**禁止**加历史标记
- 正确：`COMMENT='订单主表'`
- 错误：`COMMENT='订单主表（含审批流）'`、`COMMENT='积分账户表（对齐外部系统 balances）'`

### 1.8 废弃表的处理

**规则**：
- 废弃表必须从 DDL 中**完全删除**（包括 DROP、CREATE、字段注释、索引）
- 对应的枚举必须从 `server_enum.md` 中**同步删除**
- 删除后，**全表编号重新压缩**（不能跳号）
- 禁止在文件中留 `"已废弃"` 的注释块作为占位符

## 二、server_enum.md — 枚举定义文档规范

### 2.1 枚举标题格式

**模块分组标题**（仅用于分组，不是枚举）：

```markdown
## BASE — 跨端共享基础
```

- 格式：`## 模块代号 — 模块描述`
- 模块代号全大写（BASE / GSDAPC / GSDBPC / POINTS 等）
- 模块描述用中文

**枚举定义标题**（必须有表格）：

```markdown
## status — 订单审批状态（{prefix}_order_approval）
```

**规则**：
- 格式：`## 字段名 — 描述（关联表名）`
- 关联表名必须写，格式为 `(表名)` 或 `(表名, 条件)`
- 示例：`## status — 供应商状态（sys_user, user_type='{supplierUserType}'）`
- 禁止只写字段名：`## status`
- **禁止**在标题中加专属标记：`## sync_status — 同步状态（{prefix}_points_log，项目专属）` → 改为 `## sync_status — 同步状态（{prefix}_points_log）`

### 2.2 枚举表格格式

```markdown
| Code | 含义 | 说明 |
|------|------|------|
| 1 | 已选购 | 员工提交订单后的初始状态 |
| 2 | 已报送 | 子公司审核通过并报送给路衍 |
| 3 | 待发货 | 路衍审核通过，等待供应商发货 |
| 4 | 已发货 | 供应商已发货 |
| 5 | 已驳回 | 子公司或路衍驳回 |
```

**规则**：
- 表头固定：`Code | 含义 | 说明`
- `Code` 列可以是 int 或 string
- `说明` 列不能为空（至少写 `"—"`）
- 复杂枚举可以增加列（如 `方向`），但必须在标题中说明
- **表格下方禁止写 `> ` 开头的说明文字**
- 错误示例：
  ```markdown
  | 0 | 未同步 | 初始状态 |
  | 1 | 已同步 | Push 成功 |

  > sync_status 仅对 source_type=SUB_EXCHANGE 和 ADD_REFUND 有效。
  > Pull 写入的流水直接 sync_status=1。
  ```
- 正确示例：说明文字直接写入表格的 `说明` 列

### 2.3 模块分组

```markdown
---

## BASE — 跨端共享基础

---

## status — 订单审批状态（{prefix}_order_approval）
```

**规则**：
- 模块标题：`## 模块代号 — 模块描述`
- 模块内枚举连续排列
- 模块之间用 `---` 分隔
- 模块描述后的 `> **模块**: xxx` 和 `> **表数**: N` 等元信息**禁止保留**

### 2.4 废弃枚举的处理

**规则**：
- 废弃枚举必须**完全删除**（标题 + 表格 + 说明文字）
- 禁止留 `"已废弃"` 的占位标题
- 删除后模块内的枚举顺序保持不变，不需要重排

### 2.5 禁止混入非枚举内容

**规则**：
- `server_enum.md` **只能**包含两类内容：模块分组标题 + 枚举定义（标题 + 表格）
- 速查表、映射表、待决事项、架构说明、规则说明等一律删除或移到 `.claude/projects/` / `.claude/docs/` 下的对应文档
- 模块分组标题后**直接**跟枚举定义，中间不允许插入任何说明文字

## 三、增删表时的操作流程

### 3.1 新增表

1. 在 `server_exec.sql` 末尾按顺序追加新编号
2. 同步在 `server_enum.md` 对应模块下新增枚举章节
3. 更新文件头的 `表数: N 张`
4. **结构变更同步**：同步更新 `01-design/database.md`（DDL 快照）和 `01-design/model.md`（17 表字段索引/三层结构/业务流关联）

### 3.2 删除表

1. 从 `server_exec.sql` 中删除该表的 `DROP` + `CREATE` 整块
2. 从 `server_enum.md` 中删除该表对应的枚举章节
3. **重新压缩全表编号**（不能跳号）
4. 更新文件头的 `表数: N 张`
5. 删除模块分隔线中的 `"已改造"、"N 张中 M 张已改造"` 等历史标记
6. **结构变更同步**：同步更新 `01-design/database.md` 和 `01-design/model.md`（删除对应表的字段索引/三层结构/业务流关联段落）

### 3.3 修改表（加字段/改字段）

1. 直接修改 `server_exec.sql` 中的 `CREATE TABLE`
2. **禁止**在表注释中加 `"（★改造：+xxx）"` 等标记
3. 如果新增枚举字段，同步在 `server_enum.md` 中新增枚举章节
4. **结构变更同步**：新增字段/删除字段/字段类型变更/表关系变更属于结构变更，必须同步更新 `01-design/database.md`（DDL 字段定义快照）和 `01-design/model.md`（字段索引/三层结构/业务流关联）；纯 COMMENT 调整、状态码值补充不触发同步
